# Unknowns register

_First draft, Discovery (2026-10-18). Ongoing (plan §16.1)._

Things not yet understood that could change the design or hide a failure. Each has an experiment that would answer it. When one is answered, record the answer and where the evidence is (a `results/` folder, an ADR, a fixture), and keep the row.

| ID | Unknown | Why it matters | Experiment | Status |
|---|---|---|---|---|
| U-01 | Cold-start latency of a Python hook on Windows, with Defender scanning | Decides per-call process vs background process (D1); G7 | Spike S1 (session 2) | **answered for Windows** (`results/spikes/2026-10-18/hook_latency-windows.json`): per-call Python through Git Bash p95 77 ms, direct `-I -S` p95 48 ms, budget 50 ms (ADR-0003). Linux and macOS pending: CI job `spike-latency.yml` |
| U-02 | Does Claude Code run hooks for parallel tool calls concurrently, and in what order do Pre/Post events arrive? | Ledger locking and step attribution (FM-LED-01, FM-ADP-02) | Payload capture with a parallel tool batch; record arrival times | **answered (2.1.72, `-p`)**: both PreToolUse events arrived before either PostToolUse; the two PostToolUse hooks ran in separate processes 4 ms apart, i.e. concurrently. The ledger must lock. Evidence: `tests/fixtures/hosts/claude-code/2.1.72/0038`–`0041` |
| U-03 | Is `tool_use_id` unique across subagents and sessions? | Pairing Pre with Post events | Payload capture with a subagent | partly answered: ids look like `toolu_…` and were unique per call; a subagent's calls carry `agent_id`/`agent_type` (`0051`, `0052`). Uniqueness across sessions not proven |
| U-04 | When a hook exceeds its timeout, does the tool still run, and is PostToolUse still sent? | Fail-open/closed behaviour (D2), GAP detection | Throwaway project with a deliberately slow hook | **answered (2.1.302)** (`results/spikes/2026-10-18/hook_failure.json`): a PreToolUse hook that times out is killed at its timeout and the tool still runs, followed by PostToolUse; a crashing hook (exit 1) also lets it run; exit 2 blocks. Claude Code fails open by itself (ADR-0004) |
| U-05 | What does a PowerShell tool payload look like compared with Bash? | Windows shell capture | Payload capture on Windows | **answered (2.1.302)**: 2.1.72 has no PowerShell tool (`2.1.72/0013`). In 2.1.302 (enabled with `CLAUDE_CODE_USE_POWERSHELL_TOOL=1`) the payload has the **same fields as Bash** (`command`, `description`); a failure fires `PostToolUseFailure` like Bash; stdout uses CRLF line endings (`2.1.302/0014`, `0015`, `0085`, `0086`). Hooks that inspect shell commands must match `Bash\|PowerShell` |
| U-06 | Does PostToolUse fire when a tool fails, or is there a separate failure event? | GAP vs failed step | Payload capture with a failing command | **answered (2.1.72)**: a failing Bash command fires `PostToolUseFailure` (`error`, `is_interrupt`) **instead of** PostToolUse (`0061`). The adapter must treat it as the Post event, or every failed command becomes a false GAP |
| U-07 | Do `/rewind` restores trigger any hook event? | Outside-change detection would see them as user edits | Payload capture, then `/rewind` | open |
| U-08 | Which hook events exist in the installed Claude Code version (e.g. `PostToolBatch`, `ConfigChange`, `CwdChanged`)? | Wiring (plan §6.2), G8 config-change detection | Compare the hooks reference with captured events | **answered (2.1.72, 2.1.302)**: 2.1.72 has 21 events: no `PostToolBatch`, `CwdChanged`, `DirectoryAdded`, `FileChanged`, `PostCompact`. 2.1.302 has 33, exactly the documented list. Both lists were read from the binaries and confirmed by capture. **In 2.1.72, settings naming an unknown event register no hooks at all, without a warning** (FM-INS-03). `PostToolBatch` (2.1.302) fires once per model response, even for a single call, lists every call with its result as text (Read's is line-numbered), also fires after a failure, and carries `agent_id` inside a subagent (`2.1.302/0006`, `0052`, `0064`, `0077`) |
